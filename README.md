# Sparse-Feedback Research Backend

A prototype system for distilling sparse human expert judgments into reusable research knowledge. Originally derived from Karpathy's autoresearch framework, this system addresses the 0→1 research problem where there's no clean scalar objective and progress depends on qualitative human feedback.

## The Problem

Classic autoresearch works well for late-stage optimization with clear metrics (like validation bits-per-byte). But many important research domains lack clean objectives:

- SAR radar interpretation for defense applications
- Code agent memory design and optimization  
- Time management and productivity tool evaluation
- Any domain where "correctness" depends on human judgment of plots, cases, or outcomes

This system tackles the earlier **0→1 discovery phase** where the challenge is identifying useful constraints, invariances, anti-goals, and theories from sparse, ambiguous observations.

## How It Works

Instead of optimizing a scalar metric, this system:

1. **Stores cases** with candidate interpretations and their attributes
2. **Captures sparse human feedback** on pairwise comparisons with reasoning
3. **Distills feedback** into reusable constraints, anti-goals, and heuristics
4. **Retrieves relevant rules** for new cases based on context similarity
5. **Suggests next experiments** to fill knowledge gaps and resolve contradictions

The system transforms sparse expert judgments into a structured knowledge base that can evaluate future cases and guide research priorities.

## Quick Start

```bash
# 1. Run rule extraction from expert feedback
python distill.py

# 2. See the complete research workflow demonstration  
python demo.py

# 3. Test rule retrieval for a specific case
python retrieve.py sar_005
```

## System Architecture

The backend consists of four main components:

### Data Files
- **`cases.json`** — Synthetic SAR-like cases with candidate interpretations and numeric attributes
- **`feedback.json`** — Human expert judgments choosing winners with reasoning
- **`rules.json`** — Generated by distill.py, contains extracted knowledge

### Processing Engines  
- **`distill.py`** — Extracts constraints, anti-goals, and heuristics from feedback with deduplication and contradiction detection
- **`retrieve.py`** — Retrieves relevant rules for new cases using keyword and attribute similarity
- **`demo.py`** — Demonstrates complete workflow and research assistant capabilities

## Key Features

### 1. Rule Deduplication & Evidence Aggregation
- Merges similar rules from multiple feedback instances
- Tracks support count, confidence, and contradictions
- Calculates thresholds from actual winner-vs-loser data

### 2. Comparative Winner-vs-Loser Analysis
- Focuses on attribute differences that actually discriminate
- Avoids spurious correlations from keyword-only matching
- Generates evidence-based thresholds

### 3. Contradiction Detection & Confidence
- Identifies when "bad" traits appear in winning candidates
- Adjusts rule confidence based on contradictory evidence  
- Marks rules as `well_supported`, `uncertain`, or `contradicted`

### 4. Smart Scoring Without Stacking
- Groups rules by type to avoid double-counting evidence
- Uses confidence weighting for final decisions
- Calculates meaningful confidence from rule quality and score separation

### 5. Next Experiment Suggestions
- Identifies uncertain thresholds needing more evidence
- Suggests contradiction resolution experiments
- Finds coverage gaps in case contexts
- Acts as a research assistant, not just a classifier

## Example Usage

```python
from distill import load_feedback, load_cases, analyze_winning_patterns
from retrieve import retrieve_relevant_rules
from demo import apply_rules_to_candidates, suggest_next_experiments

# Load and process feedback
feedback = load_feedback()
cases = load_cases()
rules = analyze_winning_patterns(feedback, cases)

# Evaluate new case
case_id = "sar_005"
retrieval_results = retrieve_relevant_rules(case_id, rules, cases)
scoring_results = apply_rules_to_candidates(cases[case_id], retrieval_results['retrieved_rules'])

print(f"Winner: {scoring_results['winner']}")
print(f"Confidence: {scoring_results['confidence']:.2f}")

# Get research suggestions
suggestions = suggest_next_experiments(rules, cases)
for suggestion in suggestions:
    print(f"🎯 {suggestion['description']}")
    print(f"   Rationale: {suggestion['rationale']}")
```

## Design Philosophy

This system is **not**:
- A detector or classifier for radar/SAR data
- A standard RL/optimization system  
- An attempt to fully automate human judgment

This system **is**:
- A memory system for preserving sparse feedback structure
- A tool for extracting maximum insight from minimal human input
- A research assistant that suggests next most informative experiments
- A proof-of-concept for sparse-feedback research workflows
